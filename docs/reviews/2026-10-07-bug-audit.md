# Bug audit, 2026-10-07

**Trigger:** the user reported that the coach's voice doesn't start when they join and then start a workout. It plays only after a page refresh.

**Method:**
1. Two independent audits:
   - Codex (GPT-6.1 Sol, max reasoning, read-only).
   - Claude, which also reproduced the voice bug in Chromium with `--autoplay-policy=user-gesture-required`.
2. Each model verified the other's findings against the code, and with probes where possible.
3. Every confirmed bug was fixed with a test that fails without the fix.

Source: **C** = Codex, **A** = Claude, **C+A** = both found it.

## The voice bug

| # | Finding | Source | Fix |
|---|---|---|---|
| V1 | The recorded voice is blocked when the voice pack arrives after the Start tap. Its `<audio>` element was created later, so it was unlocked outside the gesture, and the phone refused to play it. A refresh hid this: the pack was cached and a Resume tap unlocked it. Reproduced in Chromium as 0 clips played and the "turn the voice back on" prompt shown. | C+A | One `<audio>` element per session, created before Start and unlocked in every tap (Start, Resume, voice prompt, cool-down). The pack attaches to it later (`useGuidedSession`, `primeAudio`). |
| V2 | The device-voice fallback was unlocked only when no recorded voice existed, and only once voices had loaded. | C+A | `primeSpeech()` runs in every tap, whatever has loaded. |
| V3 | "Play over my music" uses `navigator.audioSession.type = 'transient'`, which WebKit maps to AmbientSound. The silent switch and screen lock both mute that category, and it doesn't lower music as the settings hint claimed. Resume never re-applied the mode, so a fresh document stayed `auto` and could be audible after a refresh. | A (C confirmed) | The mode is applied on every tap. The settings hint now explains the silent switch. Start and paused screens show a reminder on iOS. |
| V4 | The opening line is lost when the voice arrives mid-line. Only the silent caption narrator "said" it. | A (C confirmed) | `CueScheduler.setNarrator` requeues the interrupted caption-only cue and forgets that it was said. |
| V5 | The earphone or lock-screen Play button cuts off the line being spoken. It unlocked audio while running. | A (C confirmed) | Resume is a no-op unless paused. `ClipNarrator.unlock()` does nothing while a clip is active. |
| V6 | A false "turn the voice back on" prompt appears when a clip supersedes the pending unlock (`AbortError`). | A (C confirmed) | Only `NotAllowedError` counts as blocked, and real playback clears the flag. |
| V7 | A clip stuck buffering counted as spoken: `paused` is false while buffering. When the fallback also failed, it went unreported. | C | Stalls are judged by progress. A failed fallback reports a new `silent` state, which the session screen explains. |
| V8 | The silent unlock WAV had zero samples, which a decoder may refuse. | A (C: uncertain) | Hardening: a 20 ms silent WAV. |
| V9 | The voice packs lacked 74 current sentences, including "Welcome back." and exercise names in catch-up lines. Those fell back to the robotic voice. | C+A | Catalogue regenerated and both packs re-rendered: 1346/1346 covered. |
| V10 | The coach said "1 sets of 10" and "1 carries". | A | Pluralised. |

## Safety (check-in and session)

| # | Finding | Source | Fix |
|---|---|---|---|
| S1 | An ambiguous severe low (5.5 entered in mg/dL) was dropped from the check-in, giving amber and a full workout instead of red. | C | The reading is submitted (`submitsGlucose`). |
| S2 | A ketone reading was ignored when glucose was blank: 3.2 mmol/L gave green instead of urgent. | C | Ketones are evaluated on their own. |
| S3 | "Cool-down only" after a low resumed the whole cardio block: warm-up, zone 2 or fast intervals. | C+A | New runner `seek` and `coolDownTarget`: the cardio's cool-down, or the wrap-up. The cardio is not counted as done. |
| S4 | A glucose recheck wasn't enforced. Today's Start skipped it, the sheet re-enabled Start when its timer ended, and the pre-cardio check auto-advanced unanswered. | C | A new reading is required, and Today, the Workout link and the session all honour it. The glucose checkpoint waits for an answer. |
| S5 | Editing a saved check-in dropped its blood pressure. | A (C confirmed) | The saved average is restored (`initialBp`). |
| S6 | With a new foot problem and no equipment, a recumbent bike was prescribed. | C | No machine cardio. An easy seated and floor flow fills the time instead. |

## Logging, data and other screens

| # | Finding | Source | Fix |
|---|---|---|---|
| D1 | Changing a set's weight mid-set left it "not done". A skipped step done later stayed skipped. | C+A | A step run to its end is done, and its skip is cleared. |
| D2 | A session skipped from start to finish was recorded as completed. | C | Completed needs the end reached and at least half the exercise time done. A run with nothing done is "skipped". |
| D3 | Duration was the plan position, not active time. | C | The runner tracks `activeMs` across pauses, closing and finishing. |
| D4 | "Save and exit" progress older than 18 h was lost without reaching History. | C | Banked into History (`bankProgress`, `loadExpiredProgress`). |
| D5 | Imperial weights mixed pounds and kilograms. Body metrics and bodyweight in Settings had the same problem. | C (A extended) | Stored in kg and cm, converted at the screens, with a v4 migration. |
| D6 | History edits didn't recompute volume or records. Manual finish let the last qualifying set win the record. | C | `deriveRecords` and `editSession`. |
| D7 | Rest timers drifted in the background. Supersets ignored the after-round rest. A paused rest card disappeared. | C (A: the card) | Deadline-based countdowns. The after-round rest is used. The card stays up while paused. |
| D8 | A swapped workout was lost when starting the guided session. History ignored the swap, and old guided progress resumed the old workout. | C (A extended) | A per-date `focusOverrides`, used by every plan view. Unfinished guided progress is banked on a swap. |
| D9 | Today, Workout and the session built the day's plan from different inputs. | A | All use `planFor`, which reads only earlier sessions. |
| D10 | Clear all data bounced back to Today. | C | It reloads onto onboarding. |
| D11 | Offline, the installed app couldn't open screens it hadn't loaded online. Cached chunks also missed because of `Vary: Origin` on module requests. | C (A: Vary) | Build-time precache list, a per-build cache name, and URL-only matching. |

## Second round: Codex reviews the fixes

Codex (GPT-6.1 Sol, max) reviewed every fix above. It confirmed 17 as fixed and 10 as partial, and found 10 new issues in the new code paths. Each was checked against the code, then fixed with a test:

| # | Issue | Fix |
|---|---|---|
| R1 | Previous after "cool-down only" rewound into the full interval cardio. | The runner keeps `coolDownFrom`: going back stops at the cool-down, which stays partial. |
| R2 | The no-cardio session still said "Head to the incline treadmill walk", promised 12 minutes of cardio, and repeated the welcome. | No-cardio narration: the welcome, the strength transition, a `blockIntro` for the seated flow, and a closing line before the wrap-up. 11 new lines rendered into both packs (1357/1357). |
| R3 | The v4 migration can't know historic units for users who switched preference. Old Settings bodyweight was left unconverted. | Settings bodyweight is now migrated, using the profile's kg as the reference. **Limitation:** manual sets and body metrics have no unit history, so the current preference is assumed. That is right for anyone who never switched. |
| R4 | Saving a guided run deleted another run banked earlier the same day. | Run identity is persisted with progress. A save replaces only its own record (and empty ones). |
| R5 | A new worker deleted caches that an already-open app still needed. | The previous build's cache is kept, and the app reloads once on `vite:preloadError`. |
| R6 | The first upgrade deleted cached voice clips. | Voice entries move from the old cache to `fitstrong90-voice`. Verified with an upgrade simulation. |
| R7 | `silent` replaced `blocked`, hiding the tap-to-fix button. | A block stays reported. A captions-only fallback counts as unheard. |
| R8 | Imperial bodyweight in Settings rounded each keystroke. | A draft while typing, converted on blur. |
| R9 | Banked progress lost its duration. | `bankProgress` closes the run at its last save. |
| R10 | Progress saved by an older build lost its earlier time on resume. | `rehydrate` starts from the legacy estimate. |
| — | Next could skip the unanswered glucose check (S4). A blank re-submission cleared a recheck (S4). | Next waits for an answer. A new reading is required after a recheck (`submitBlocked`). |
| — | A manual "Finish" with nothing done counted as completed (D2). | `finishedStatus`: completed at ≥ 50 % of sets, otherwise partial or skipped. |
| — | Device speech that never started counted as spoken (V7). | It reports failed unless `onstart` fired. **Accepted:** a clip that stalls part-way through has been partly heard, so the watchdog still ends it. |

## Third round: Codex confirms

Codex confirmed most second-round fixes, and found 3 more issues plus 4 partial fixes. All are now fixed:

| Issue | Fix |
|---|---|
| A kept older cache answered before the current one (`caches.match` searches in creation order), so an update could serve the old `index.html` offline. | The current build's cache, or the voice cache for voice, answers first. Verified with an upgrade simulation using a marked old `index.html`. |
| A manual workout finished as partial or skipped lost its controls. | A status badge, **Resume Workout** (reopens it) and **Redo Workout**. |
| Some no-cardio welcomes (other schedules' day names, and a recovery session without a walk) weren't recorded. | Catalogue grid widened, packs re-rendered (1367/1367). A new test fails whenever any catalogue sentence lacks a clip in any pack. |
| The bodyweight migration's 1 kg tolerance missed weights that had changed a little. | 10 % of the profile weight; kg and lb differ 2.2-fold, so they can't be confused. |
| A later load error turned "blocked" into "failed", hiding the fix button. | "blocked" clears only when sound actually plays or a tap unlocks it. |
| Speech that the system cancelled before it started counted as spoken. | Reported as unheard. Our own stop() still counts as an abort. |
